# jjmap

## Commands

- Bun is the runtime, package manager, bundler and test runner: `bun install`, `bun run <script>`, `bunx <pkg>`. Do not use Node, npm, Vite or Jest.
- Before committing: `bun test && bun run typecheck && bun run lint && bun run format:check && bun run test:web`. Fix formatting with `bun run format`.
- Varlock loads env (`import "varlock/auto-load"`) from `.env.schema` plus the gitignored `.env.local`; `bunfig.toml` disables Bun's own `.env` autoload. Never put real credentials or `op://` references in tracked files.
- Prefer Bun APIs (`Bun.serve` with HTML imports, `Bun.file`) over Node equivalents where the code already does.

## Effect

- Server and core code uses Effect v4, pinned exactly to `effect@4.0.0-rc.117` (the version the `effect-ts` skill vendors); any other `@effect/*` package must match. Load the `effect-ts` skill before writing Effect code.
- Capabilities are `Context.Service`s with `layer` statics (or `of`/`fromX` constructors): `JmapClient` (`src/mailbox.ts`), `Jev` (`src/classify.ts`), `Paths` (`src/usage.ts`), `Connector` (`src/triage.ts`), and in `src/web/api.ts` `Backend` (implemented by `LiveBackend` in `backend.ts` and `DemoBackend` in `demo.ts`) and `Api`. Tests provide synthetic layers or `Service.of` values (`src/test-support.ts` has `fakeJmap`); anti-slop forbids module mocking.
- Errors are `Schema.TaggedError`s with safe `message`s; provider details stay in `cause`. Use `Effect.fn` for named effectful functions, `catchTag` rather than `_tag` comparisons, and `Result`/`Option` predicates.
- Decode every I/O boundary with Schema: `config.json`, `categories.json` (`CategoriesFile`, which also runs `validateDrafts`), `state.json`, HTTP bodies, NDJSON events, Jev answers, and JMAP `/set` responses. `src/json-file.ts` reads and atomically writes schema-checked JSON.
- Env is still loaded by `varlock/auto-load`; read it afterwards through Effect `Config` (`Config.Redacted` for `JMAP_BEARER_TOKEN` and `TYPESAFE_API_KEY`).
- `Message` and `Folder` (`src/mailbox.ts`) are the narrow email and mailbox contracts jjmap reads; full JMAP objects satisfy them, so fixtures need no casts.
- UIs stay plain React with no Effect runtime in components. Browser code may import browser-safe schemas (`src/domain.ts`, `src/categories.ts`, `src/plan.ts`, `src/web/model.ts`) to decode responses; keep those modules free of server imports. CSS custom properties are typed by `src/web/css-variables.d.ts`.
- `bun run lint` registers the anti-slop generic and Effect plugins (vendored under `tools/oxlint/anti-slop/`) at `error`; fix findings properly rather than suppressing them.

## Web triage

- `src/tui/main.tsx` is a lightweight CLI dispatcher. Load Varlock and the terminal renderer dynamically; `--web --demo` must never load credentials or the live backend.
- `src/web/` uses Bun HTML imports and React DOM. Browser TSX files need `/** @jsxImportSource react */` because the root TypeScript JSX source is `@opentui/react` for the terminal.
- Browser imports of server types must be type-only. Do not pull mail services, filesystem APIs, or credentials into the browser bundle.
- The web server defaults to loopback; `--web --host IP` opts into one specific IPv4 interface (for example, Tailscale), never a wildcard. The API requires the per-launch token, exact bound Host, and same-origin JSON POSTs. Only explicit Start authorizes paid classification and live updates; preview is read-only.
- Categories are runtime config (`src/categories.ts` is pure and browser-safe; `src/category-store.ts` owns `categories.json` IO and folder creation). Only `other` (leave alone) and `review` (UI bucket) are built in; never reintroduce hardcoded category ids outside `DEFAULT_CATEGORIES` seeds and demo fixtures. Categories point at mailbox ids, not names. First visit (`boot.categoriesSaved === false`) opens the required `categories` setup step; later it is reachable from the overview's Categories button. The editor reuses the overview's folder tiles (`FolderArtwork` from `src/web/folder-artwork.tsx`) with a dashed + tile to add a category; the side panel column is always present (nothing is selected by default; it shows a "No category selected" empty state, or only its header while loading, and the Done button must not change the header height) so selecting a tile fills it with fields without shifting the layout (stacked on phones). `POST /api/categories` uses the same guards, returns 409 while busy, and discards any prepared batch. The overview hides mailboxes that are category targets; sorting tiles use the overview's stat layout (EMAILS count and SORTED share of the emails sorted so far). Only move targets get their own folder tile; categories that keep mail in place (`folderId: null`) and `review` share one tile named after the source folder, each shown as a sticky note (category color and count) that bumps when its mail lands. Demo categories live in memory; `--demo-unconfigured` (e2e tag `@unconfigured`) starts at setup.
- Web navigation is (first-run setup →) folder overview → scope configuration → sorting. The chosen folder is the source, and web runs always sort untriaged mail (the `ScopeRequest` schema rejects other filters), so scope configuration only offers count, date range, and workers. Overview fronts show two same-sized accent-colored counts of current non-draft contents (not historical totals): EMAILS total at bottom-left and UNCLASSIFIED (lacking `$triaged`) at bottom-right, each — when unknown and None when zero, with no envelope mark; no text renders below overview folders (nested paths live only in the title and aria-label). Overview folders with zero unclassified mail are disabled and muted (unknown counts stay selectable). Overview tiles and sorting destinations share `.folder-rows`: step-1-sized, fixed-width tiles centered in a flex wrap capped at `--columns` (half the tiles, rounded up), so they form two balanced, tightly spaced rows with the shorter row centered; they wrap further only when the space can't fit that many. Sorting percentages remain batch destination shares. Folder faces/tabs use subtle `--accent` color mixes on both screens. `/api/folders` is read-only; count queries are bounded to four folders (eight queries), queued reads stop when leaving the overview, and unknown totals remain null. Folder listing must paginate beyond 200 entries. The live backend reuses the mailbox list and per-folder counts for `READ_TTL_MS` (30 s, settled values only); Refresh folders sends `?fresh=1` to bypass it, category Save clears it, and every `apply` clears counts even when unconfirmed. `begin` and category Save always validate against a fresh list. Every step is full width and fills the viewport height on desktop; the shared bottom `.controls` bar is pinned to the bottom (`margin-top: auto`) as a grid with `.controls-start`, `.controls-center`, and `.controls-end` slots so actions stay left and right even when one side is empty, and every step's loader shares the centered middle slot: back on the left (Folders on options, Options on sorting, replaced by Load fresh batch once a run is done) and Next/Start/Stop on the right; step 1 has Refresh folders on the left and Categories on the right (its settled status line replaces the loader in the center slot); the categories step has Folders (hidden on first run, replaced by status) and Save. Result events carry per-email usage so the sorting step's EST. COST updates live from `boot.pricing` (Jev's published rate in `DEFAULT_PRICING`); the `done` event's usage stays authoritative.
- Loading states report real server progress, never fake progress. `/api/bootstrap`, `/api/folders`, and `/api/preview` stream NDJSON `LoadEvent`s (`stage` with optional done/total, `folder`, then `result` or `error`) only when the client sends `Accept: application/x-ndjson`; otherwise they return the same JSON as before. Backends receive a `LoadReporter` whose methods return Effects (`SILENT` for JSON callers); expected failures fail with `LoadError` (status for JSON, message for streams), and anything else (including `BackendError` and defects) is sanitized in both modes. Interruption replaces abort signals: leaving a load interrupts its remaining reads. Stage order and labels live in `LOAD_STAGES` (`src/web/model.ts`). Folder counting reports done/total and emits each settled folder so tiles fill in live; preview reads email details in `READ_CHUNK` (50) chunks via `mailbox.fetchBatch` for a determinate bar. `StageList` in `app.tsx` (✓ done, pulsing current, dim pending, count plus bar when known, indeterminate bar otherwise) always renders in the bottom bar's `.controls-center` slot: overview bootstrap and folder counts, the options preview, and (without a bar) the run-startup phase stepper. The classification progress bar is a run meter, not a loader, and stays beside the CLASSIFIED stats. `GhostFolder`/`Shimmer` placeholders (from `src/web/folder-artwork.tsx`) remain for layout before bootstrap/folder listing and categories; shimmers show only while a fetch is in flight (settled nulls stay —). The demo backend adds small synthetic delays so stages are visible. All loading motion is disabled under reduced motion.
- Wizard transitions use native View Transitions with a CSS entry fallback and reduced-motion support. Options → Next opens the read-only stack preview; only the separate Start sorting button on that screen can begin a run. Next waits only for the new DOM, never for animation completion. Preserve the Next/Start re-entry guards and Stop handling before/during preflight; startup phase events contain only elapsed timings, not mail content.
- Animate confirmed mail updates only. Flights use a continuous 480 ms arc with no upright hold. The pile drops in on Next, not again on Start; the first confirmed result settles any unfinished entrance immediately. Neither the entrance nor the wizard crossfade may delay or obscure flights: the sorting scene has its own View Transition name, and only its static chrome (queue label, caption, destinations) fades in on mount. The wizard group never morphs geometry (steps differ in width); snapshots crossfade unscaled in place. Entering the sorting step, the outgoing step clears first (120 ms) and the scene, chrome, and pile drop start after a 90 ms delay; the stage stays transparent so the old step fades rather than being cut off. Reduced motion skips the drop and flights. Preserve partial results and paid usage on Stop, disconnect, or failure. Demo and browser tests must remain entirely synthetic unless a user separately authorizes a bounded paid run.
- The elapsed timer above classification progress stays ready at zero in the stack preview, starts at accepted Start and freezes on the terminal run event (or stream/request failure), not after animations settle. Keep running/complete/stopped/error states distinct in text and color. Timer ticks stay inside the memoized timer component, never rerendering the card tree.
- `src/web/pipeline.ts` bounds inference plus pending writes to the selected worker count (default 4, maximum 8; `Effect.forEach` concurrency, with a job holding its slot until its write settles). One writer (a one-permit `Semaphore`) coalesces ready results without timers; runs fork detached with `startImmediately`, so disconnects never interrupt paid work mid-email; `prepareApplier` validates configured target folders once per run and never creates folders (only category Save does). Stop finishes already-started work only, and failed/ambiguous writes prevent later queued writes. Keep TypeSafe's per-email questions grouped and SDK rate-limit backoff enabled.
- Demo folder contents are in-memory synthetic fixtures; only confirmed mock moves change their counts. Browser tests create a fresh server per test to avoid cross-test state leaks.
- `bun run web:demo` previews animation. `bun run dev` runs the same synthetic demo with browser HMR and console echo (`--dev`); server-side changes still need a restart because `bun --hot` would re-serve on a new port and token. `bun run test:web` runs Chrome/Playwright tests under `src/web/e2e/*.pw.ts` (the `.pw.ts` suffix excludes them from `bun test`). Browser artifacts belong in ignored `.scratch/`.

For more information, read the Bun API docs in `node_modules/bun-types/docs/**.mdx`.
